Section 01 — Project Overview

The Problem of Optimal Choice

How do solvers find the best answer among millions — or billions — of possibilities? This project unpacks the intelligent search strategies hidden inside optimization software.

This project grew out of a Management Science course on Integer Programming and optimization algorithms. The central question: when we need whole-number decisions — how many units to produce, which routes to take, which projects to fund — how does software actually find the best answer without exhaustively testing every option?

🔢

Integer Programming

A class of optimization problems where decision variables must take integer (whole number) values. Unlike continuous LP, the feasible region is discrete — making exact solutions far harder to find. Used in scheduling, logistics, finance, and resource allocation.

🌿

Branching

When a relaxed LP solution produces a fractional value (e.g. x = 2.7), the solver "branches" by creating two sub-problems: one where x ≤ 2 and another where x ≥ 3. This partitions the search space without losing any feasible integer solutions.

✂️

Bounding

Each node in the search tree has an upper bound (best possible value if we ignore integrality). If this bound is worse than the best integer solution found so far, the entire sub-tree can be pruned — eliminating vast regions of the search space in a single step.

🌳

Search Trees

The visual and structural backbone of Branch & Bound. Each node represents a sub-problem with additional constraints. The tree grows as branches are explored and shrinks as nodes are pruned, guiding the solver toward optimality efficiently.

🎯

Optimization

The process of finding the best possible value of an objective function — subject to constraints — across all feasible solutions. In integer programming, this requires both the precision of exact methods and the efficiency of intelligent pruning strategies.

⚡

LP Relaxation

Before branching, the solver solves a "relaxed" version of the problem where integrality is ignored. This gives an upper bound on the optimal integer solution and provides a fractional variable to branch on — the entry point to the entire B&B process.

Why these concepts matter in decision-making

Logistics

Vehicle routing and delivery scheduling require integer assignments of routes to trucks — no half-routes allowed.

Finance

Capital budgeting decisions — which projects to fund — are inherently binary: you either fund a project or you don't.

Manufacturing

Production planning involves integer quantities of products, machines, and shifts that cannot be fractional in practice.

Staffing

Workforce scheduling requires whole numbers of employees per shift, per role, per location — a classic IP structure.

Section 03 — Evidence

Reading notes

Cornell Method

Branch & Bound (BB) for MILP/IP/BP

Why BB needed? Simplex → fractional values for integers. BB = Simplex + decision tree to enforce integrality.
Problem types: BP (all binary), IP (all integer), MILP (mixed).
Relaxation: Integer {L..U} → continuous [L,U]. Root node = full relaxation.
Tree basics: Nodes = different LP relaxations. Edges = new constraints (x ≤ floor, x ≥ ceil).
Branching: Binary → x=0 and x=1. Integer → x ≤ floor(val) and x ≥ ceil(val).
BB (Best Bound): Best objective among active nodes. For max: upper bound.
BI (Best Incumbent): Best integer-feasible solution. BB ≥ BI for max; BB ≤ BI for min.
Optimality Gap (OG): |(BB-BI)/BI|×100%. OG=0% → optimal proven.
Fathoming (stop node): 1) infeasible, 2) integer solution (update BI), 3) fractional but worse than BI.
Branching strategies: Backtracking (LIFO, efficient tableau reuse) vs Jumptracking (any active node, fewer nodes).
Separation rules: Use down/up penalties from tableau. Branch on highest penalty.
Algorithm (max): Relax → root → branch → solve child → fathom → update BB/BI/OG → repeat until gap < ε or time limit.
Complexity: BB exact but slow for large problems. Heuristics faster; BB gives bounds.

Section 04 — What Did I Learn?

Knowledge, Skills & Reflection

Studying Integer Programming and Branch & Bound didn't just teach an algorithm — it revealed how good decisions are actually found under real-world constraints.

🔢

Integer Programming

Understood how integer constraints fundamentally change the nature of optimization — moving from convex continuous regions to discrete feasible sets that cannot be solved by simple calculus or LP methods alone.

🌳

Branch & Bound

Learned the mechanics of systematic partitioning: how branching creates valid sub-problems and how bounds allow entire branches to be eliminated without ever evaluating them — the key to tractability.

📊

Search Trees

Discovered how the structure of the B&B tree encodes the history of decisions made and the constraints added at each stage — and why the tree's depth and breadth vary dramatically with problem structure.

⚙️

Optimization Logic

Grasped how solvers balance exploration and exploitation: pursuing promising branches deeply while maintaining awareness of the global best bound to know when no further search is necessary.

✂️

LP Relaxation

Understood the role of the LP relaxation as both a bound generator and a branching guide. A tight relaxation makes B&B efficient; a loose one leads to excessive branching.

🎯

Pruning Strategies

Learned the three pruning conditions — infeasibility, bound dominance, and integer feasibility — and how each contributes to reducing computational effort in large-scale IP problems.

On Scale

Large problems cannot always be solved by brute force. Even modest IP problems with 30 binary variables have over a billion possible combinations — exhaustive search is practically impossible, which is exactly why intelligent search strategies exist.

On Strategy

Optimization software uses intelligent search strategies, not magic. The efficiency of Branch & Bound comes entirely from the quality of its bounds and the cleverness of its pruning rules — there is real mathematical structure being exploited at every step.

On Process

Good solutions often emerge gradually. The best integer solution found early acts as a benchmark that makes later pruning decisions possible. The first feasible solution found is rarely optimal — but it enables the search to become dramatically more focused.

On Sensitivity

Small changes can affect the entire search process. A tighter bound at the root node can eliminate entire sub-trees before they are explored. Conversely, a weak relaxation can cause the algorithm to explore an exponential number of nodes unnecessarily.

On Practice

The gap between theory and software is instructive. Learning to use solvers made the abstract algorithm feel concrete — seeing infeasibility messages, sensitivity outputs, and solution times connected the mathematics to real computational behaviour.

On Decision-Making

Integer Programming is fundamentally about making discrete choices under constraints — which mirrors almost every real management decision. The discipline of formulating a problem clearly before solving it is itself a valuable skill far beyond optimization.
