01 — Definition

What is the
Traveling Salesman?

Imagine a salesman who must visit a set of cities — each city exactly once — and then return home. The goal is to find the shortest possible route that accomplishes this.

TSP belongs to the class of NP-hard problems — meaning no known algorithm can guarantee an optimal solution in polynomial time as the number of cities grows.

Routes = (n − 1)! / 2

For n = 30, this exceeds the estimated number of atoms in the observable universe.

02 — Mechanics

How Does
It Work?

TSP can be modeled as a graph: cities are nodes, and routes between them are weighted edges. The objective is to find the minimum-weight Hamiltonian cycle.

03 — Solution Methods

Approaches to
Solving TSP

Brute Force
O((n−1)!)

Enumerate every permutation. Guaranteed optimal but impractical beyond 12 cities.

Exact
Nearest Neighbor
O(n²)

Greedy heuristic: always go to the closest unvisited city. Fast but ~20-25% longer.

Heuristic
2-Opt
O(n²) per pass

Local search: reverse segments if it reduces total length. Highly effective.

Local Search
Genetic Algorithm
Configurable

Inspired by evolution: selection, crossover, mutation. Scales to thousands of cities.
